Q-02 · Высокий приоритет · кому: Product Owner / Бизнес-аналитик

Отправляется ли повторный push в текущем месяце, если клиент изменил порог расходов, когда ранее по прежней настройке push уже отправлялся (п. Ф-3 заявляет «максимум один push в месяц», а п. Ф-4 — «независимо от истории предыдущей настройки»)?

Связано: F-02, R-06 (Ф-3), R-07 (Ф-4)

8. Итог

Можно ли начинать разработку: нет. Можно ли начинать тестирование (тест-дизайн): нет.

Документ содержит два критических противоречия в ключевой бизнес-логике (определение месяца операции для расчёта бюджета и правила отправки push при изменении порога), а также существенные ошибки в спецификации REST API и информационной безопасности. Начинать разработку и тестирование до устранения дефектов нельзя, так как реализация приведет к некорректным финансовым расчетам и переделкам.

Правило решения: есть критичный дефект → «нет»; есть только существенные → «условно»; только незначительные → «да» (methodology/severity.md).

Что исправить в первую очередь:

  1. Устранить противоречие между Ф-2 и Критерием приёмки №2 (F-01): зафиксировать единый подход к определению месяца операции (по дате совершения или дате клиринга).
  2. Устранить конфликт между Ф-3 и Ф-4 (F-02): четко определить, отправляется ли push при изменении порога, если в текущем месяце лимит push уже исчерпан.
  3. Исправить REST API спецификацию (F-18, F-19, F-22): изменить HTTP-метод сохраняющего запроса /alerts/saveLimit с GET на POST/PUT, перенести параметры из Query в JSON Request Body.
  4. Исправить обработку ошибок в API (F-20): при ошибке валидации возвращать корректный HTTP-статус 400 Bad Request вместо HTTP 200 OK с result: ERROR.
  5. Дополнить правила расчёта расходов (F-08, F-09, F-12): описать сценарии включения опции в середине месяца, обработки возвратов прошлых периодов и повторных превышений порога.
  6. Привести в соответствие единицы измерения и типы данных (F-15, F-21): унифицировать типы полей (integer/string) в API и единицы хранения денег (тенге/тиыны) в модели данных.
  7. Заполнить метаданные документа и критерии приёмки для требований Ф-1 и Ф-4 (F-07, F-24).
